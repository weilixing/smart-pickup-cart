## 一、课题名称

**基于 ROS2 的智能取货搬运机器人设计与实现**

## 二、课题来源与研究背景及意义

### 2.1 课题来源

自选课题（工程实践类）。

### 2.2 研究背景

随着电子商务与智能制造的快速发展，仓储物流环节的自动化、智能化需求持续增长。以亚马逊 Kiva 系统为代表的"货到人"仓储机器人，通过自主移动机器人（AMR, Autonomous Mobile Robot）驮运货架至工作站，大幅提升了分拣效率并降低了人力成本，已成为智慧物流的标志性应用。与此同时，机器人操作系统 ROS（Robot Operating System）及其第二代 ROS2 在学术界与工业界得到广泛采用，其提供的 SLAM（同步定位与建图）、自主导航（Nav2）等成熟软件栈，使中小型团队也能够构建具备自主移动能力的机器人系统。

在高校工程教育中，自主移动机器人是融合嵌入式系统、传感器技术、自动控制、软件工程与机器人学等多学科知识的综合实践载体。构建一辆能够完成"接单 → 取货 → 定点投递 → 返回"完整业务闭环的取货搬运机器人，具有较强的综合性与工程挑战性。

### 2.3 研究意义

1. **工程实践意义**：完成从机械结构、嵌入式固件到上层智能软件的全栈式机器人开发，覆盖"感知—决策—执行"完整链路，锻炼系统工程能力。
2. **技术探索意义**：采用"通用处理器 + 微控制器"异构双板分层架构，实践 ROS2 软件生态（SLAM、Nav2、EKF 多传感器融合）与实时嵌入式控制的职责划分与协同方法，该架构与工业界主流 AMR 产品一致。
3. **应用参考价值**：取货机构借鉴亚马逊 Kiva"潜入顶升"式方案，以较低成本复现工业级"货到人"搬运流程，对小型仓储、图书取送、楼宇配送等场景具有参考意义。

## 三、国内外研究现状

### 3.1 国外研究现状

国外仓储机器人起步较早。2008 年，Wurman 等人系统阐述了 Kiva 仓储机器人系统的多车协调方法，其"潜入货架底部顶升驮运"的机构形式与"地标网格 + 集中调度"的导航方式成为行业范式，该系统后被亚马逊收购并大规模部署。Fetch Robotics、Locus Robotics 等公司随后推出基于 ROS 的移动操作与协作搬运机器人。在软件层面，Open Robotics 主导开发的 ROS2 针对实时性、多机通信与产品化需求对 ROS 进行了重构（基于 DDS 通信中间件）；slam_toolbox（Macenski 等）提供了生产可用的激光 SLAM 方案；Nav2 导航框架以行为树与插件化控制器实现了高可靠自主导航，二者已成为移动机器人事实上的标准组件。

### 3.2 国内研究现状

国内仓储机器人产业近年发展迅速，极智嘉（Geek+）、快仓、海康机器人等企业推出了规模化商用的潜伏顶升式 AGV/AMR 产品，在电商仓、制造车间大量落地；新松、优艾智合等企业在复合机器人（移动底盘 + 机械臂）方向亦有布局。在高校层面，全国大学生智能汽车竞赛、中国机器人大赛等赛事推动了自主移动机器人技术的普及，多所高校开设了基于 ROS 的机器人实践课程。

### 3.3 开源生态与教学平台现状

开源硬件平台方面，TurtleBot3/TurtleBot4、linorobot2、古月居 OriginBot 等平台提供了"单板计算机 + 单片机运动控制板"的参考设计，证明了低成本 ROS2 移动机器人的可行性；micro-ROS 项目则探索了在微控制器上直接接入 ROS2 网络的路径。总体来看，现有教学平台多以"巡航避障"为演示目标，**面向具体业务流程（取货—运输—投递—返回）的完整闭环演示平台较少**，且取货机构多采用结构复杂的机械臂，调试门槛高、演示成功率难以保证。

### 3.4 现状小结与本课题切入点

综合上述现状，本课题的切入点为：以异构双板（通用处理器 + 微控制器）分层架构为硬件基础，复用 ROS2 成熟软件栈实现自主定位与导航，取货环节借鉴工业界验证充分的"潜入顶升"机构以降低机械与控制复杂度、提高演示成功率，最终构成一个面向完整业务流程、结构可靠、成本可控、可进一步扩展（机械臂视觉抓取）的智能取货机器人原型。

## 四、研究目标与主要内容

### 4.1 研究目标

设计并实现一辆基于 ROS2 的智能取货搬运机器人，在 3m × 3m 室内场地内，无人干预地完成"接收订单 → 自主导航至取货点 → 确认并取走货物 → 运输至指定投递点 → 放下货物 → 返回出发点待命"的完整闭环演示，并具备扩展机械臂视觉抓取的演进能力。

### 4.2 主要研究内容

1. **异构双板硬件平台设计**：以 OrangePi AIpro（8T）为上层计算平台（运行 Ubuntu 22.04 + ROS2 Humble），以瑞萨 RA8（Cortex-M85 内核，480MHz）微控制器为底层实时控制单元，完成电源分配、传感器与执行器选型及整机电气设计。
2. **底盘运动控制与里程计**：在 RA8 上实现四路编码器采集、双侧轮速 PID 闭环、航迹推算里程计，以及看门狗急停、软启动等安全机制；设计双板串口通信协议，实现速度指令下发与里程计、IMU、RFID 等状态上报。
3. **环境感知与自主导航**：基于激光雷达与 slam_toolbox 实现场地 SLAM 建图；采用 robot_localization 扩展卡尔曼滤波融合轮式里程计与 IMU；基于 Nav2 实现点到点自主导航与动态避障。
4. **潜入顶升式取货机构与货物识别**：设计车顶丝杆顶升平台与配套货架托盘（净空 130mm 供车体潜入），实现"钻入—顶升—驮运—放下"取货动作；采用 RFID（RC522）实现货架身份确认。
5. **任务调度状态机**：基于 Python 与 Nav2 Simple Commander 实现"接单 → 取货 → 投递 → 返回"的业务状态机，具备导航失败、取货失败等异常的处理能力。
6. **（拓展）机械臂视觉抓取升级**：预留 ArUco 标记识别节点，二期可加装 6 自由度机械臂，实现基于视觉伺服的抓取式取货，与顶升式并存。

## 五、拟解决的关键问题

1. **异构双板的可靠通信与失效安全**：上下位机通过串口交换控制指令与传感器数据，需设计带帧头、长度与校验的鲁棒协议，并实现通信中断看门狗急停，保证失控安全。
2. **低净空潜入动作的精确对位**：货架净空仅 130mm，整车需精确停靠于货架正下方。拟采用"EKF 融合定位 + 货架托盘导向锥机械容错 + 必要时超声波末端微调"的组合策略，吸收 ±15mm 级定位误差。
3. **多传感器融合的定位置信度**：滑移转向的四轮底盘轮式里程计误差较大，需通过 EKF 融合 IMU 角速度抑制航向漂移，并以激光 SLAM 全局校正。
4. **全流程状态机的鲁棒性**：导航失败、RFID 未读到、顶升不到位等异常均需可检测、可恢复，保证连续多次演示的成功率。

## 六、研究方案与技术路线

### 6.1 总体架构

系统采用分层架构，自上而下分为决策层、感知层与执行层：

```
┌────────────────────────────────────────────────────┐
│ 决策层  task_orchestrator（任务状态机，Python）       │
│         Nav2（路径规划/导航）  slam_toolbox（建图）    │
├────────────────────────────────────────────────────┤
│ 感知层  YDLIDAR（/scan）  IMU  编码器  RFID  USB相机  │
├────────────────────────────────────────────────────┤
│ 执行层  RA8：电机PID / 里程计 / 顶升丝杆 / 限位        │
│         ▲ 自定义串口协议（115200 8N1，帧校验）          │
│ 计算层  OrangePi AIpro：Ubuntu 22.04 + ROS2 Humble  │
└────────────────────────────────────────────────────┘
```

- **OrangePi AIpro（8T）**：运行全部 ROS2 节点（导航、建图、融合、任务调度），其 8TOPS NPU 为二期视觉目标检测升级预留算力。
- **瑞萨 RA8**：承担全部硬实时任务（1kHz 电机 PID、编码器计数、限位保护、RFID 读取），通过 UART 与 OrangePi 通信；不引入 micro-ROS，以降低工具链复杂度。

### 6.2 硬件设计方案

| 模块 | 选型 | 说明 |
| --- | --- | --- |
| 上层主控 | OrangePi AIpro（8T） | 已有；Ubuntu 22.04 + ROS2 Humble |
| 底层控制器 | 瑞萨 RA8 开发板 | 已有；Cortex-M85 @480MHz |
| 底盘 | 4WD 差速底盘 + 编码器电机（MG513 级） | 甲板 200×160mm，Ø85 轮 |
| 激光雷达 | YDLIDAR X2 / LD19 | 车头低位安装（离地约 90mm，低于货架净空） |
| IMU | MPU6050 / ICM20948 | 接 RA8，随遥测帧上报 |
| 视觉 | USB 广角相机 | 免驱；二期 ArUco 识别 |
| 取货机构 | NEMA17 + T8 丝杆顶升平台（行程 50mm）+ 双限位 | 车顶潜入式 |
| 货物识别 | RC522 RFID + 标签卡 | 标签贴托盘底面中心 |
| 电源 | 3S 18650 + 独立稳压 | 主控与电机供电隔离，共地 |

关键机械约束：货架托盘台面 160×160mm、腿高 140mm（净空 130mm）；整车最高点 ≤115mm；标准演示货箱 120×120×100mm、≤500g。

### 6.3 软件设计方案

ROS2 功能包划分（已建立代码骨架）：

| 功能包 / 节点 | 运行位置 | 职责 |
| --- | --- | --- |
| `pickup_description` | OrangePi | 整车 URDF/xacro 模型与 TF 树 |
| `motor_bridge` | OrangePi ↔ RA8 | `/cmd_vel` 下发；`/odom`、`/imu/data_raw`、`/rfid_id`、顶升状态上报 |
| `robot_localization`（EKF） | OrangePi | 轮式里程计 + IMU 融合，发布 `odom→base_footprint` |
| `ydlidar_ros2_driver` | OrangePi | 发布 `/scan` |
| `slam_toolbox` | OrangePi | 场地建图 |
| `nav2_bringup` | OrangePi | 定位、路径规划与导航 |
| `lift_controller` | OrangePi | 顶升 `/lift/set` 服务，等待限位到位反馈 |
| `aruco_detect` | OrangePi | ArUco 标记识别（二期） |
| `task_orchestrator` | OrangePi | 业务状态机：接单 → 取货 → 投递 → 返回 |
| RA8 固件 | RA8 | 电机 PID、里程计积分、串口协议、RFID/IMU/顶升驱动 |

任务状态机状态转移：`IDLE → NAV_TO_PICKUP → CONFIRM_RFID → LIFT_UP → NAV_TO_DELIVER → LIFT_DOWN → NAV_HOME → DONE`，任一环节失败进入 `FAILED` 并触发重试或安全停车。

### 6.4 双板通信协议

自定义串口协议（115200 8N1，小端）：帧格式 `[0xAA, 0x55, CMD, LEN, PAYLOAD…, CRC]`，CRC 为 CMD 至 PAYLOAD 逐字节 XOR。下行含目标速度（20Hz）、顶升指令、心跳；上行含里程计（50Hz）、IMU（100Hz）、RFID 事件与顶升到位状态。协议设计兼顾解析鲁棒性（帧头重同步、CRC 丢弃错帧）与实现简洁性，ROS 侧 Python 解析器与固件侧 C 头文件一一对应。

### 6.5 取货机构与货物识别方案

- **一期（本课题主体）**：潜入顶升式。车顶顶升平台收回时整车高 ≤115mm，可潜入净空 130mm 的货架底部；RC522 读到托盘底部标签确认身份后，丝杆顶升 50mm 使货架离地，驮运至投递点后降下放回。机构仅含一个直线自由度，控制简单、可靠性高。
- **二期（拓展）**：机械臂抓取式。加装成品 6 自由度总线舵机机械臂，货箱贴 ArUco 标记（同时提供身份与 6DOF 位姿），由视觉伺服完成抓取；与顶升式形成双模式演示。

### 6.6 开发与验证方法

采用迭代式开发，分两期推进：一期优先跑通顶升式完整闭环（兜底可演示成果），二期升级机械臂视觉抓取。各阶段验证方法：

1. **单元级**：电机 PID 阶跃响应整定；里程计直线 1m 与原地 360° 标定；协议串口回环测试。
2. **集成级**：EKF 融合后定点重复精度测试；Nav2 目标点到达精度与避障测试。
3. **系统级**：连续 10 次完整闭环演示，统计成功率与单次耗时；注入异常（遮挡货物、路径阻挡）验证状态机恢复能力。

## 七、预期成果与考核指标

1. **实物样机**一台：完成装配、联调，可现场演示完整取送闭环。
2. **软件成果**：ROS2 功能包若干与 RA8 固件一套（仓库化管理，含协议与设计文档）。
3. **毕业论文（设计报告）**一篇。
4. **主要技术指标**：
   - 导航目标点到达误差 ≤ ±10cm，取货潜入对位误差 ≤ ±15mm（导向锥吸收）；
   - 单次完整闭环（取—送—回）≤ 90s；
   - 连续 10 次闭环演示成功率 ≥ 90%；
   - 通信中断 500ms 内电机急停，顶升双限位保护可靠动作。

## 九、可行性分析

1. **技术可行性**：SLAM、导航、EKF 融合等核心算法均有 ROS2 成熟开源实现（slam_toolbox、Nav2、robot_localization），社区文档完善；嵌入式侧电机 PID、串口通信为经典技术，RA8（Cortex-M85 @480MHz）算力充裕；顶层任务调度以 Python 状态机实现，技术风险低。取货机构采用工业界验证充分的潜入顶升方案，避开机械臂运动学的高调试门槛，一期闭环成功率高。
2. **经济可行性**：两块主控板（OrangePi AIpro、RA8）为现有设备，新增采购仅底盘、雷达、传感器与机构件，合计约 ¥1,250；二期机械臂为可选升级（约 ¥600~800）。整体成本可控。
3. **进度可行性**：采用"先闭环、后增强"的两期迭代路线，第 10 周即可形成可演示的最小成果，后续为增强与打磨，即使二期机械臂进度不及预期，也不影响课题主体目标的达成；软件骨架与协议文档已提前完成，降低了集成风险。
4. **条件可行性**：实验场地为普通室内平地（3m × 3m）即可；结构件采购成品打印件，无需专用加工设备；开发工具（e2 studio、ROS2、RViz）均为免费软件。
